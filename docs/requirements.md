# supu-portfolio 要件定義書

Nov 27, 2026 · @supu

## 1. 概要

就職活動・インターン応募で採用担当に見てもらう、スマホ優先の1ページのポートフォリオを、supu361.dev で公開する。

| 項目 | 内容 |
| --- | --- |
| 目的 | 応募書類や面接の前後に、作品・技術・経歴・人柄を短時間で伝える |
| 想定読者 | 企業の採用担当・エンジニア（応募書類の URL から訪れる） |
| 公開方針 | 検索には載せない（noindex）。URL を知っていれば誰でも見られる |
| 主な閲覧環境 | iPhone 15 Pro Max（横幅 430px）。PC・タブレットにも対応 |
| 公開先 | supu361.dev（Cloudflare） |
| 予算 | 0 円 |
| 名前の表記 | ハンドル名「Supu」のみ。本名は出さない |

作品は個人の制作物だけを載せる（自分の寄与が少ないハッカソンの成果物は除外）。試作（HTML）の最新版を、この要件定義の見た目の正本とする。

### 1.1 背景

応募書類や面接では、作品の中身や開発の進め方を短時間で伝えきれない。書類に URL を書けば、採用担当が事前・事後に好きなだけ確かめられるようにする。あわせて、このサイト自体を TypeScript・Next.js・Tailwind CSS の学習と、仕様から作る開発の実践の場にする。

## 2. コンセプト

タイトルは「我逢人」。音楽と制作物の話を、最初の画面の演出だけで伝え、それ以外は普通の言葉と定番の構成で見せる。

- **タイトル**：我逢人（がほうじん）。禅の言葉で、Mrs. GREEN APPLE の曲名でもある。歌詞は使わない
- **添える一文**：すべての出逢いが、いまの私をつくっている。（1行のみ）
- **カラオケの扱い**：最初の画面の「音程バー」と「歌詞テロップ」にだけ使う。見出しやボタンをカラオケの言葉に置き換えることはしない（選曲・延長などは不採用）

- **言葉のトーン**：盛らない。面接で話している内容（面接キーワードシート）とずれないこと

余白と文字の大きさは画面幅に合わせて連続的に変え、切り替わりの境目でガタつかせない。iPhone の Dynamic Island とホームバーには重ならないようにする。

### 4.4 動き

- 音程バーと Works の波形は、画面外・アプリ非表示のときは描画を止める
- 見出しやカードは画面に入ったときにふわっと表示、Skills は右から順に並ぶ
- 端末で「視差効果を減らす」がオンのときは、すべての動きを止め、静止した状態で全情報を見せる

## 5. 文言・表記

サイト上に書く細かい文言と、載せる情報の範囲を次のとおりとする。法的な判断は一般論に基づくもので、専門家の確認を経たものではない。

### 5.1 サイト上に書くもの

| 項目 | 文言・内容 |
| --- | --- |
| ページタイトル（OGP） | supu-portfolio |
| 説明文（OGP） | Supu のポートフォリオ |
| 共有時の画像（OGP） | 我逢人のタイトルを置いた 1200×630 の画像 |
| アクセス解析の一文 | 本サイトでは Cloudflare Web Analytics でアクセス数を集計しています。Cookie は使用せず、個人を特定する情報は収集していません。 |
| 最終更新日 | フッターに「最終更新 YYYY.MM.DD」。公開のたびに自動で入れる |
| 著作権表記 | © 年 Supu（年は自動） |
| 外部リンク | 新しいタブで開く。読み上げ向けに「新しいタブで開きます」を付ける |
| 画像の代替テキスト | スクリーンショット・動画ごとに、何が写っているかを書く |
| 404 ページ | 一言とトップへのリンク |

Cookie を使わないため、同意を求めるバナーは置かない。フッターの一文と実際の動きが一致するように、外部に情報を送る埋め込み（YouTube や Google Fonts など）は使わない（6章）。

### 5.2 載せる情報の範囲

- **名前**：ハンドル名「Supu」のみ。本名は出さない
- **大学・学年**：東京工科大学 コンピュータサイエンス学部 3年、28卒
- **インターン先**：社名は伏せる。一般的な言語・フレームワーク名（PHP / FuelPHP）は載せてよい。社内システム名、取引先、開発中の機能の中身、数値は載せない。技術名・業界・期間などの組み合わせで会社が特定できる書き方は避ける
- **問題解決型インターン**：課題の中身は守秘のため、学びの一言のみ
- **連絡用メール**：普段使いのアドレスは載せない。Cloudflare Email Routing で専用アドレス（例：contact@supu361.dev）を作り、手元に転送する

### 5.3 第三者の名前・ロゴ・フォント

- **我逢人・Mrs. GREEN APPLE**：禅の言葉・曲名として使い、歌詞は使わない。アーティスト名（Mrs. GREEN APPLE・藤井風）は「好きなもの」としてのみ書き、公式との関係を思わせる使い方（ロゴや写真）はしない
- **GitHub・X・Zenn のロゴ**：自分のアカウントへのリンクとしてのみ使う。形と色の比率は崩さない
- **フォント**：3種とも自由に使えるライセンス。ページ上の表記は不要

### 5.4 作品の見せ方

Vocal Analyzer はユーザー登録があるため、ポートフォリオからはデモにリンクせず、動画とスクリーンショットで見せる。GitHub を公開する場合は、パスワードや API キーがコードや履歴に残っていないかを公開前に確認する。「録音データは保存せず削除」などの記述は、アプリの実際の動きと一致させる。

## 6. 技術構成とインフラ

Next.js で作ったページを静的ファイルとして書き出し、Cloudflare から supu361.dev で配信する。サーバーで動く処理は持たない。

### 6.1 採用技術

| 役割 | 技術 | 選んだ理由 |
| --- | --- | --- |
| 言語 | TypeScript | 型で作品・経歴データを安全に扱える。現場の標準 |
| フレームワーク | Next.js 16（App Router、静的書き出し `output: 'export'`） | 就活で評価されやすい。静的書き出しでサーバー機能の脆弱性の影響をほとんど受けない |
| スタイル | Tailwind CSS v4 | 色とフォントを `@theme` で変数として定義でき、試作の CSS 変数をそのまま移せる |
| 配信 | Cloudflare Workers（静的アセット配信） | ドメイン・解析・メール転送と管理画面をまとめられる。無料 |
| ドメイン | supu361.dev（Cloudflare で管理中） | 既に所有 |
| アクセス解析 | Cloudflare Web Analytics | Cookie 不使用、個人を特定しない、無料 |
| 連絡用メール | Cloudflare Email Routing | 専用アドレスを作り、手元のアドレスに転送 |
| フォント配信 | next/font（自分のサイトから配信） | 外部にアクセス情報を送らない。表示も速い |

&#91;embedded content: システム構成 · 配信・解析・メール転送\]

ソースを push すると自動でビルド・配信される。閲覧者のブラウザから外に出る通信は、すべて Cloudflare の中で完結する。

### 6.2 実装の決めごと

- 画面は基本すべてサーバーコンポーネント（ビルド時に HTML になる）。動く部品だけをクライアントコンポーネント（`'use client'`）にして、読み込む JavaScript を最小にする
  - クライアント：音程バー、歌詞テロップ、Works の波形、詳細ウィンドウ、Career の線、ナビの現在地
- アニメーションは Canvas と CSS で書き、アニメーション用のライブラリは入れない
- 作品・スキル・経歴・プロフィールは `data/` の型付きファイルに分け、画面の部品を触らずに更新できるようにする
- デモ動画は数十秒の MP4（H.264）に圧縮して自分のサイトから配信する。YouTube は埋め込まない（Cookie を使うため）。Cloudflare の静的配信は 1 ファイル 25MB まで
- 画像は WebP に変換してから置く（静的書き出しでは Next.js の画像最適化が使えないため）
- 最終更新日はビルド時に自動で埋め込む
- noindex はページの `robots` メタデータと、配信時の `X-Robots-Tag` ヘッダーの両方で設定する。robots.txt でクロールを禁止しない（7章）

| --- | --- |
| 表示速度 | Lighthouse（モバイル）の Performance 90 以上。最初の画面がすぐに出ること。動画は詳細を開いたときに読み込む |
| アクセシビリティ | Lighthouse の Accessibility 95 以上。文字と背景のコントラストは WCAG 2.1 AA。タップできる部分は 44px 以上。キーボードだけでも操作でき、詳細ウィンドウは Esc で閉じる |
| 動きへの配慮 | 端末の「視差効果を減らす」がオンなら、すべての動きを止める |
| プライバシー | Cookie・localStorage を使わない。外部への送信は Cloudflare Web Analytics のみ。フォント・動画・画像はすべて自分のサイトから配信 |
| 検索への掲載 | 載せない。noindex をメタデータと `X-Robots-Tag` ヘッダーで指定。robots.txt でクロールを禁止すると検索エンジンが noindex を読めなくなるため、禁止しない |
| 対応環境 | iPhone（Safari）を最優先。Android（Chrome）、PC の Chrome・Safari・Edge の最新版 |
| ライト・ダーク | 端末の設定に合わせて自動で切り替え、どちらでも崩れないこと |
| 運用コスト | 0 円（Cloudflare の無料枠）。ドメイン更新費のみ |
| 更新のしやすさ | 文章の更新は `data/` のファイルだけで済むこと |

## 8. セキュリティと運用・保守

入力欄もログインもない静的サイトなので、守るべきは「秘密情報を公開しないこと」と「依存パッケージを最新に保つこと」の2点に絞られる。

### 8.1 セキュリティ

- HTTPS のみで配信する（.dev ドメインは HTTPS が必須）
- 配信時にセキュリティヘッダーを付ける（Content-Security-Policy、X-Content-Type-Options、Referrer-Policy、Permissions-Policy）。CSP で許可する外部の通信先は Cloudflare Web Analytics だけにする
- API キーやパスワードはリポジトリに置かない。Cloudflare の認証情報は GitHub の Secrets で管理する
- Next.js はほぼ毎月セキュリティ修正が出るため、静的書き出しでも依存パッケージを更新する（Dependabot で通知を受ける）
- AI が生成したコードは、本人が内容を確認してから取り込む

### 8.2 テスト

| 種類 | 方法 | 合格基準 |
| --- | --- | --- |
| 表示の確認 | Playwright で iPhone 15 Pro Max・タブレット・PC の幅、ライト・ダークを撮影して目視 | 崩れ・はみ出しがない |
| 機能 | 3.8 の受け入れ条件を実機で確認 | すべて満たす |
| 性能・アクセシビリティ | Lighthouse（モバイル） | 1.4 の目標値 |
| プライバシー | ブラウザの開発者ツールで Cookie と通信先を確認 | Cookie なし、外部通信は Cloudflare のみ |
| 型・書式 | TypeScript の型チェックと Lintを PR ごとに自動実行 | エラー 0 |

### 8.3 運用・保守

| 作業 | タイミング |
| --- | --- |
| 経歴・作品の更新 | インターンの開始・終了、作品の更新時（次は 12 月末の長期インターン終了） |
| 依存パッケージの更新 | 月 1 回、またはセキュリティ修正の通知が来たとき |
| 閲覧数の確認 | 応募の後、必要なとき |
| ドメインの更新 | 年 1 回（自動更新を有効にする） |
| バックアップ | 不要。ソースは GitHub、公開物はそこから再ビルドできる |

公開後に不具合があった場合は、Cloudflare で直前の版に戻してから修正する。

## 10. 用語

| 用語 | 意味 |
| --- | --- |
| noindex | 検索エンジンに「このページを検索結果に載せないで」と伝える指定 |
| OGP | URL を SNS やチャットに貼ったときに出る、タイトル・説明・画像のカード |
| 静的書き出し | ページをあらかじめ HTML ファイルとして作っておき、サーバーでの処理なしに配信する方式（Next.js の `output: 'export'`） |
| サーバー／クライアントコンポーネント | 前者はビルド時に HTML になる部品、後者はブラウザで動く部品（`'use client'`） |
| Cloudflare Workers | Cloudflare の配信・実行環境。今回は静的ファイルの配信だけに使う |
| Email Routing | 自分のドメインのアドレスに届いたメールを、普段のアドレスに転送する Cloudflare の機能 |
| CSP | ページが読み込んだり通信したりできる相手を限定するセキュリティの仕組み |
| 視差効果を減らす | 端末のアクセシビリティ設定。オンのときは動きを止める（prefers-reduced-motion） |
| 試作 HTML | デザインを決めるために作った 1 ファイルの画面。見た目の正本 |
